# 卡牌设计准则

本准则统一道具卡、机会事件和财富事件的名称、梗、台词、故事、效果说明与插画。卡名直接突出梗、招式或名场面；台词像场景里的人说的话；故事用动作和反差把梗讲出来；插画表现同一个瞬间。出处保留在内容源表和素材记录中。

2026-10-18 合并已确认的卡名精简规则与 Q 版图片设计原则。插画以「眉头一皱」（原样张名「韩立眉头一皱」）、「全速前进」「草丛三兄弟」三张确认图为视觉基准，沿用本文件路径供已有素材记录引用。

## 卡面各字段的分工

| 字段 | 写法与作用 |
| --- | --- |
| 名称 | 直接点出梗、招式、道具或名场面，简短、好记，方便玩家口头说出来 |
| 台词 | 场景内的一句喊话、吐槽或招牌话，补充情绪与笑点 |
| 故事描述 | 交代人物、动作和反差，让台词与插画有具体场景可依 |
| 效果说明 | 独立、准确地说明玩法、对象、数值、时机和必要限制 |
| 出处 | 记录作品、人物、原作情节或网络梗来源，供核对和生成图片使用 |
| 插画 | 用人物、表情、站位和动作表现该场景，不把说明文字画进图里 |

## 名称

- 直接突出梗本身，不在卡名前加作品、游戏、平台、人物介绍或题材标签。例如「DNF命运硬币」改为「命运硬币」，「星露谷丰收」改为「回村种地」，「钟离开盾」改为「固若金汤」。
- 人物名或称呼本来就是完整梗的一部分时保留，例如「提莫必须死」「马什么梅」「多比是自由的」「熹妃回宫」。不机械地删除所有专有名词。
- 能独立成立的招式、道具和梗名直接使用，例如「任意门」「筋斗云」「神罗天征」「地爆天星」「龙卷风摧毁停车场」。不再补作品前缀或解释性后缀。
- 优先采用原梗里的招牌话、动作或反差，例如「我能打一整天」「眉头一皱」「我架枪，你发财」。避免只剩人物姓名，也避免把名字写成故事摘要。
- 名称只表达一个核心意思，不堆叠「作品＋角色＋技能＋用途」。例如「发现·探险者的抉择」简化为「发现」，「ROOM·错位空间」简化为「ROOM」。
- 同一道具池中，不同效果尽量使用不同名称，避免玩家选错。当前旧抢牌卡使用「以彼之道，还施彼身」，任意两人换位卡保留「斗转星移」；不同池对同一梗的复用按各自卡面内容判断。

## 梗与选材

- 一张卡围绕一个明确的梗、招式、名场面或生活反差展开，不堆砌多个作品和互不相关的流行词。
- 笑点来自场景中的人物反应、行动和结果。少写「这是某作品的经典梗」「致敬某角色」等介绍，直接让故事发生。
- 名称、台词、故事和插画必须指向同一个梗。人物、服装、道具和场景按确认内容核对，不从沿用的 skinId 猜题材。
- 保留原作人物身份与场景的关键关系；卡面改编不冒充原作情节。不能确认的原句不标作逐字引用，不能确认的出处不写成事实。
- 熟悉出处的人能认出梗，不熟悉的人也能从短故事读懂眼前发生了什么。作品说明放在出处字段，不挤进卡名或台词。
- 生活类、网络梗和原创场景同样适用这些原则，不强行套原作人物，也不让每张卡都讲发财、收租或拆房。

## 台词

- 写场景中人物会说的一句短话，优先保留已确认的招牌话、口头禅、喊招、吐槽或反应。例如「来个回血，别又劈我！」能直接承接命运硬币的风险与笑点。
- 语气贴合说话者和当时的处境，口语自然、节奏清楚。不要为了押韵、生造金句或解释出处而改变角色的说话方式。
- 台词与名称互相补充，不只是重复标题，也不承担整段故事或玩法说明；喊招本身就是梗时可以重复招式名。
- 不把「获得现金」「免除租金」「抽取道具」等界面效果直接塞进无关的原作台词。场景本身在谈工资、购物或施工时，可以自然提钱和工作。
- 原句和改编句区分记录。只有核对过的原句才按原句使用，改写内容不声称是原作逐字台词；本次名称精简不同时重写已确认台词。

## 故事描述

- 写一个短场景，交代必要的起因，让人物做出具体动作，再用反应或结果形成反差。避免人物介绍、作品简介和抽象的感想堆叠。
- 用表情、对话、站位和动作讲梗，不在结尾追加「这就是某某梗」或解释笑点。
- 保留辨认场景需要的人物名、地名、道具和关键细节。卡名精简不等于故事里也不能出现原作人物。
- 故事和台词的情绪应一致，插画能从中选出一个明确瞬间。多个镜头的故事，图片只表现其中最有辨识度的一幕。
- 玩法单独由效果字段说明；不因卡牌能收租、拆房或给钱，就把原本无关的名场面改写成大富翁经营故事。

## 效果说明与内容维护

- 效果说明以实际机制为准，说明作用对象、发动时机、金额或次数、成功概率及会影响决策的限制。简短卡名和台词不替代规则说明。
- 同效果的多个卡面可以有不同梗、故事和图片；名称和皮肤数量不额外改变该效果的抽取概率。
- 三份内容源表为 `docs/content/cards.md`、`chance.md`、`fortune.md`；通过 `scripts/sync-game-content.py` 同步运行 JSON，并核对前端缺省名称及当前卡面总览。
- 只改名称时，保留 skinId、机制、完整参数身份、概率、等级、台词、故事和图片绑定。已有手牌继续使用取得时保存的名称、文案和效果，不因改名而重抽或迁移。
- 素材生成清单中的历史名称、原始提示词和验证记录保留生成时原文，通过 skinId 与当前内容对应；图片总览的显示名称随当前卡池同步。

## 插画风格与比例

- 精致二次元手绘赛璐璐插画，约两头身，大头、短身体、小手脚，轮廓清楚圆润。
- 眉毛、眼神、嘴形和姿态明显夸张，具有表情包和轻喜剧动画的梗感；主角之间的反应差异要读得出来。
- 色彩明亮，阴影清晰，整体偏暖；按题材使用青绿、蓝金、橙黄等配色，不强制所有作品使用相同背景。
- 保留角色的标志性发型、服饰、武器和道具。原作人物遵循各自身份，生活类原创人物以成年角色为主，避免所有卡面重复同一张脸。
- 以已确认的 Q 版样张作风格参考。旧写实 3D 样张和苏暖暖主题不再作为新卡面的画风基准。

## 插画题材与场景

- 从当前启用卡池的名称、台词、场景描述，以及内容源表中的出处确定题材。皮肤 ID 可能沿用旧题材，不能从 ID 推断新角色。
- 一张图选一个明确的喜剧瞬间，用站位、表情和动作讲清梗。人物一般占画面约 70% 至 80%，背景只保留辨认场景所需的线索。
- 人物与场景贴合原作或引用的网络梗。玩法效果独立由组件显示，不额外把收租、拆房、现金和骰子硬塞进无关的原作场景。
- 原文故事本身包含工资、购物、施工等内容时可正常表现。重点是叙事来源，不能将所有题材改成通用富翁场景。
- 可使用汗滴、夸张震惊光芒、速度线和小碎步动势等漫画表现。轻松、可爱、滑稽，无血腥或伤口特写。
- 不画卡名、台词、说明、等级、UI、水印和文字气泡；手机、屏幕、文件和招牌使用不可读的抽象色块。

## 插画构图与文件

- 正方形满版单幅插画，无卡框、无留白拼版。人物面部、关键道具与动作尽量保留在中央安全区域，缩成手牌小图仍能看清。
- 每个启用皮肤对应一张独立图，不因同效果而共用不贴题的插画。保留稳定的 skinId，图片绑定使用 skinId，不使用本局随机卡牌 ID。
- 原图保留在生成工具的用户图片目录，项目仓库只记录来源路径、提示词、摘要和 OSS 地址。
- 上传前等尺寸转码 WebP，默认 quality 90、method 6，不裁切、不缩放；有透明度时保留透明度。
- 通过项目既有 PicGo 图床上传 OSS，复用项目域名。不得在规范、脚本输出或素材记录中保存上传密钥。
- 每张图核对 HTTP 200、image/webp、Content-Length、Content-MD5 与本地文件一致，核对成功后才更新 card-illustrations.json。
