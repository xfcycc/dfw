## 实际金额与保存

新局将全部内容现金档冻结到本局经济快照，覆盖键为：

```text
content.<池>.<机制>.<完整参数id>.<现金字段>
```

例如机会收益基准 200：`content.chance.income.amount-200.amount`；赌博组合先按字段名排序得到完整参数身份，其 `wager` 和 `prize` 使用各自键。皮肤身份不参与金额键。同一组合下所有皮肤使用同一实际金额，无固定覆盖时默认 ×2；步数、次数、中奖概率及防御比例不乘倍率。超限每张折现使用 `handDiscard`，基准 200，默认 400。

默认经济配置已固定覆盖 R 现金道具为 1200／1600、SR 现金道具为 2400，以及机会榜底救济和财富榜底额外补助为 3000；财富落格者默认基础奖励仍为 800，同人兼得时合计 3800。覆盖值为最终到账，不再乘倍率；原参数 ID、等级与抽取概率保持不变。完整键与新局生效边界见 [金额配置](game-configuration.md#金额配置)。

手牌保存完整 `ContentResult`（机制、参数、皮肤、实际效果文案）和 `kind`。后续修改配置不会重新抽取已经获得的牌，也不会重新计算其现金参数；旧 `{id,kind}` 手牌继续原六卡 DSL。已提交的事件结果、排名目标、选择候选、赌博样本、灾害损失与补偿样本，以及效果队列、父费用和流程等待任务共同保存。恢复仍校验同一数据库的 Flowable 实例、任务和决策绑定，不自动重建流程、迁移旧引擎或清库。

免费升级卡确认成功才消费，取消或无目标保留。免费建筑按本局标准建造成本估值。新抽补给先保存全部牌，再开放超限选择；本人必须按当前动态上限恰好选留对应张数，其余逐张折现，确认在同次事务内完成。旧同格式超限存档也需要本人选留；有费用时保存父等待位置，已有交易则等报价处理后整理，不清除费用或报价。

## 选择和付款协议

新增输入仍走原 `GameCommand` 信封及命令摘要去重：

| 操作 | 字段 | 用途 |
| --- | --- | --- |
| `contentDecision` | `decisionId`，按选择附 `accept`、`tileId`、`cardId` 或 `keepCardIds` | 免费升级、直升满级、自家／对手全毁、赌博、解控、超限选留 |
| `paymentDefense` | 可选 `decisionId`，可选 `cardId`，无卡代表放弃 | 本笔至多一种免租或减半，之后才可筹款或资产抵债 |
| `card` | 原有 `cardId` 与目标字段 | 新道具与旧手牌共用入口，自选遥控传 `point` |

公开待选仅标为 `choice` 和实际选择者，不含具体选择类型、候选卡、数量或返回队列。私人 `choice` 包含选择身份和候选项，目标确认时服务端再次检查；拒绝非法选择保留牌、主动次数和原选择。关闭界面弹框不会放弃服务器选择，可以从行动栏重新打开。相关选择者离线则暂停，无倒计时。

强制费用先对原正租金消费翻倍状态，再自动消费下次免付款状态；仍有费用时必须选择一种卡或放弃。`pending.originalAmount` 保存防御前费用，`defenseResolved` 保存已选择事实；减半减免额为向下取整，房东仅收最终债务余额。资产抵债后不能再减免一次。旧版本已进入支付／筹款／报价等待的债务继续其余额，不新增一次按余额减免的机会。

全体扣款复用既有固定座位目标和逐人费用帧，实际付款人选择自己的防御，整批结算后才判胜。自愿赌博仅用已有现金，先扣下注再按中奖奖金到账，不额外返本金；不能在该窗口抵押或交易筹款。加码与骰子一次连续移动，正负移动继续处理路障与起点奖励，只结算最终落点。每次实际落入机会或财富格都会抽取对应事件；事件前进或后退后的落点继续结算，可连续触发事件。沿用效果队列的自动结算上限，异常联动超限时报告错误并回滚当前事务。
