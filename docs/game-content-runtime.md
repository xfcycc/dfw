# 完整道具与事件内容接入

2026-10-13 按已确认策划实现。源码包含全部 342 条素材：121 条机会、110 条财富、111 张道具；财富再次行动的 12 条素材权重为零，实际启用 330 条。UR 与指定传送无主地产保留暂缓。五档地价和新局 25% 基础租金保持已确认配置。

## 配置与分层抽取

三份事件文件新增 `content.mechanisms`。每个机制配置整数百分比 `weight`，池内合计 100；机制下 `groups` 表示金额档，档权重合计 100，无档的机制只有 `default`；每档 `parameters` 是去重后的完整数值组合，等概率选择；确定组合后仅在其 `skins` 内按 R／SR／SSR＝6／3／1 加权。稀有度没有金额或机制效果，重复皮肤不增加某个参数的概率。

财富纯现金的小／中／大档权重为 70／25／5；机会收益和费用为 80／19／1。替代掷骰的固定步数分支为 14%，自选遥控分支为 4%，合计 18%；其余道具按主稿确认概率。定向补给先等概率选择免租／免费升级／遥控，再抽该类型的匹配卡面。赌博按七种去重完整组合选择。

`ContentCatalog` 在启动时校验概率合计、参数唯一、范围、皮肤身份及停用模板。机会和财富同名原素材由 `chance_`／`fortune_` 前缀区分。原 `events` 与六种 `cards` DSL 保留已排队效果和无皮肤旧手牌的兼容配置；新的机会、财富和道具抽取全部使用分层内容，不将原小池叠加抽取。

文案原稿在 `docs/content/`，运行使用 JSON，不在对局中解析 Markdown。修改素材后使用：

```sh
python3 scripts/sync-game-content.py
```

此命令只同步三份内容配置，不执行对局、测试或构建。机制概率在脚本 `WEIGHTS` 中定义；运行可使用现有 `GAME_RULES_*` 环境变量指定独立外部 JSON。默认 JSON 中停用素材保留原文案。

## 实际金额与保存

新局将全部内容现金档冻结到本局经济快照，覆盖键为：

```text
content.<池>.<机制>.<完整参数id>.<现金字段>
```

例如机会收益基准 200：`content.chance.income.amount-200.amount`；赌博组合先按字段名排序得到完整参数身份，其 `wager` 和 `prize` 使用各自键。皮肤身份不参与金额键。同一组合下所有皮肤使用同一实际金额，默认 ×2；步数、次数、中奖概率及防御比例不乘倍率。超限每张折现使用 `handDiscard`，基准 200，默认 400。

手牌保存完整 `ContentResult`（机制、参数、皮肤、实际效果文案）和 `kind`。后续修改配置不会重新抽取已经获得的牌，也不会重新计算其现金参数；旧 `{id,kind}` 手牌继续原六卡 DSL。已提交的事件结果、排名目标、选择候选、赌博样本、灾害损失与补偿样本，以及效果队列、父费用和流程等待任务共同保存。恢复仍校验同一数据库的 Flowable 实例、任务和决策绑定，不自动重建流程、迁移旧引擎或清库。

免费升级卡确认成功才消费，取消或无目标保留。免费建筑按本局标准建造成本估值。新抽补给先保存全部牌，再开放超限选择；本人必须恰好选留六张，其余逐张折现，确认在同次事务内完成。旧同格式超限存档也需要本人选留；有费用时保存父等待位置，已有交易则等报价处理后整理，不清除费用或报价。

## 选择和付款协议

新增输入仍走原 `GameCommand` 信封及命令摘要去重：

| 操作 | 字段 | 用途 |
| --- | --- | --- |
| `contentDecision` | `decisionId`，按选择附 `accept`、`tileId`、`cardId` 或 `keepCardIds` | 免费升级、自家毁楼、赌博、解控、超限选留 |
| `paymentDefense` | 可选 `decisionId`，可选 `cardId`，无卡代表放弃 | 本笔至多一种免租或减半，之后才可筹款或资产抵债 |
| `card` | 原有 `cardId` 与目标字段 | 新道具与旧手牌共用入口，自选遥控传 `point` |

公开待选仅标为 `choice` 和实际选择者，不含具体选择类型、候选卡、数量或返回队列。私人 `choice` 包含选择身份和候选项，目标确认时服务端再次检查；拒绝非法选择保留牌、主动次数和原选择。关闭界面弹框不会放弃服务器选择，可以从行动栏重新打开。相关选择者离线则暂停，无倒计时。

强制费用先对原正租金消费翻倍状态，再自动消费下次免付款状态；仍有费用时必须选择一种卡或放弃。`pending.originalAmount` 保存防御前费用，`defenseResolved` 保存已选择事实；减半减免额为向下取整，房东仅收最终债务余额。资产抵债后不能再减免一次。旧版本已进入支付／筹款／报价等待的债务继续其余额，不新增一次按余额减免的机会。

全体扣款复用既有固定座位目标和逐人费用帧，实际付款人选择自己的防御，整批结算后才判胜。自愿赌博仅用已有现金，先扣下注再按中奖奖金到账，不额外返本金；不能在该窗口抵押或交易筹款。加码与骰子一次连续移动，正负移动继续处理路障与正向起点，只结算最终落点。每回合最多抽一次事件。

## 卡面和隐私投影

`ContentCard.vue` 共用名称、稀有度、素材类型、实际发动时机、台词、描述、实际效果结构；`ContentChoice.vue` 使用现有 `Modal.vue`、表单和按钮。所有玩家可以看公开事件卡面、资产榜和持续状态。具体补给事件与道具只进入 `player:private`：普通补给和定向补给整张事件均私有，公共日志只记“收到一份私人补给”，不展示名称、台词、效果、牌型或数量。

抢夺由服务端从对方真实手牌随机转移一张，双方只获得这张牌的私人结果，不查看对方其他牌；对方无牌时不消费抢夺卡或主动次数。`StateViews` 明确投影公开状态与各人的手牌、选择和最近私人结果，内部选择帧及返回位置不直接作为公共快照。

## 地图目标选择与路障范围

点击中央手牌后打开使用弹窗：路障／拆房选择合法地块，换位／抢夺选择玩家；只选择目标不提交命令，确认后发送原 `card` 命令。免费升级仍先由服务端生成 `free_upgrade` 的 `tileIds`，继而在选择弹窗中通过原 `contentDecision` 确认；取消保留卡和主动次数。免费升级与自家毁楼事件复用合法目标弹窗，其他私人选择仍沿用原组件和命令。

路障的合法目标为前方 1～6 格内任意没有路障的地块，包括起点、机会、财富与监狱。新卡、旧卡配置及效果执行入口使用同一地块类型边界；移动截停、免疫保留路障及落点结算机制保持原样。已有冻结卡面不迁移，前端路障说明采用当前通用规则。

局内操作集中在地图中央，铺满内圈空白：左侧城市新鲜事（实时最新在下、历史查询），下方融合聊天区，聊天标题右侧展示当前行动、待办入口及收到报价／等待回应提醒，交易／掷骰／结束行动按钮与发送消息同排；右侧展示排行与资产概览，全部资产在弹窗管理，六张手牌在两列下方同排展示。买地、升级、付款、防御及私人选择均使用临时弹窗；接收方收到新交易报价时自动打开交易弹窗，同一报价同步不重复弹出，收起后可从聊天区提醒或交易入口重开。交易操作按钮按内容宽度排列，长文案可换行。关闭只收起界面，不提交放弃、拒绝或取消命令；报价草稿、卡牌参数、目标与私人选择输入继续保留，用户从聊天区或原入口重新打开。免费升级仅明确点击“取消并保留卡／放弃升级”才发送原 `contentDecision accept=false`；自家毁楼及强制选择仍需确认，收起后不能跳过待办。卡牌准备期间仍禁用掷骰、结束行动和发起交易，并显示继续使用入口。聊天沿用 `chat` 命令，不推进游戏行动任务，记录存入原公开日志与历史表。
