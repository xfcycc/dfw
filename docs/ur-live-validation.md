# UR 正式链路本地检查记录

2026-11-06。本轮完成 48 张 UR 专属分镜的正式本地链路核对；未部署、未提交。

## 检查方法与边界

新建隔离恢复房间，使用本地双玩家 WebSocket 会话发送正常游戏命令。按用户授权准备手牌、现金、合法地产、破损证据、防御牌及已抽中的事件队列；不增加正式发牌入口，不绕过出牌、材料、选择、支付或防御校验。所有修改过的数据库局面先备份，只批量更新新房间；原存档不覆盖。

事件队列模拟的是“抽中哪张事件”，目标抽取、补偿、胜负、升级、防御和私人候选仍由服务端计算。金额参数按房间冻结配置准备。检查记录不是单元测试或冒烟测试脚本；未执行前端 build。

48 张均取得了匹配稳定 skinId 的实际公开演出片段。这个覆盖口径是每张的主入口，不表示每张在所有人数、所有随机结果、所有防御组合及所有设备上的穷尽验收。

## 本轮修复

- 尘歌壶在重新分配之前采集地产外观，返回实际变化的两处目标；复查为 1／1 → 0／3。
- NETA_DAMAGE 纳入真实建筑变化采集；流萤破盾后降级结果不再被前面的清盾片段遮住。
- 神君标记保存已公开的原卡面；锁定阶段高亮真实地产，下一个本人回合的追击继续使用神君专属身份。旧存档无来源时继续通用表现。
- 令咒增加施术者到实际受令者的前奏，后续按服务端原路径移动。
- 一次公开结算内，同一 UR 实例只在主作用段播放完整招式。优先选择有实际建筑变化的片段；其余片段继续原移动、状态和金额反馈。不同卡面事件保留各自演出。
- 新消耗的防御 UR 使用完整分镜；已有状态的短触发提示仍保留。全图拆除事件补齐来源，区分龙卷风与大闹天宫。
- 天才俱乐部、粉色奇迹在公开发动时展示招式，候选与重塑结果继续走私人投影。公开事件揭卡只显示主体，避免在揭卡和棋盘各重复一次完整动画。
- 队列提前完成时，即使最终快照沿用 motion id，也立即取消旧加载回调和动画层；修复跳过后遮罩滞留至原计时器结束的问题。
- 观战跟随模式在招式期间增加棋盘高度，适用于手机和桌面；结束后恢复原布局。

## 页面与生命周期检查

使用真实 RoomView，检查 1280×720 桌面和 390×844 手机视口。代表画面覆盖流萤、矢量反射、封印卡、龙卷风、天才俱乐部、粉色奇迹、亚丝娜和建设效果。检查透明边缘、主体与目标定位、棋盘裁切及自然收场；原有 48 张逐卡预览记录见 `ur-unique-choreography.md`。

- 手机普通布局和默认观战跟随布局均查看；完整地图、目标高亮和主体保持在棋盘区域。
- 桌面跟随模式复查：1280 像素视口下，演出棋盘由约 164 像素扩大到 337 像素；代表帧为 `/private/tmp/dfw-ur-live-follow-desktop.png`。
- 播放中模拟 visibilitychange：旧层 0，队列已释放，恢复前台不补播。
- 播放中模拟 prefers-reduced-motion 媒体变化：旧层 0，结果直接同步，恢复动态不补播。
- 提前完成当前片段：修复后旧层 0，实际升级结果仍为 3 级。
- 自然结束、后续事件衔接：最终无旧层、无播放锁定，查看页面错误日志未见运行错误。
- 后台与减少动态使用临时本地检查控件触发浏览器事件，属于应用事件处理验证；不是操作系统切后台、真实系统设置或 iOS／Android 真机性能验收。静态分镜和重播、切换仍沿用上一轮预览检查记录。
