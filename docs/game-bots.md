# 规则机器人

房主在大厅选择简单、普通或困难后点击“添加机器人”，可以在各机器人席位上修改难度或移出席位。机器人自动准备，与真人共用 2～6 人人数限制、地图、经济规则和行动权限，游戏开始后不修改难度。大厅和资产排行显示机器人及其难度。

添加时从当前房间所有玩家尚未使用的头像中随机选择一个，昵称使用头像名称加 `(机器人)`，例如 `露娜(机器人)`。头像去重仅在机器人加入时进行；后续玩家换头像不触发重新分配，已有机器人也不自动改名或换头像。

## 决策与难度

策略位于 `backend/src/main/java/com/dfw/application/BotPlanner.java`，仅接收 `StateViews.publicRoom` 与对应机器人的 `StateViews.privatePlayer` 投影。没有传入正式内部房间、其他玩家手牌、种子、未来骰子、预抽取的活动结果、子弹位置、未领取红包金额、隐藏盲盒或其他人的秘密选择。多人活动中，公开的已提交名单只用于判断是否还需要输入。

| 难度 | 前瞻与风险 | 交易和出牌 |
| --- | --- | --- |
| 简单 | 估计下一次行动，现金储备较少 | 现金压力、双方排名和连片以较低权重参与买卖、互换和抵债，可容忍约 10% 的综合估值损失 |
| 普通 | 估计未来三次个人行动的折扣落点、租金支出和后续位置价值 | 平衡双方现金、成交后排名与连片，接受报价最低综合收益约为付出估值的 2%，主动报价另需明确动机及更高收益 |
| 困难 | 将前瞻扩展至六次个人行动，保留更高风险储备并增加现金不足的损失权重 | 提高现金压力、领先者获益、排名变化及连片权重，最低综合收益约为付出估值的 4% |

所有难度均能主动交易、回应报价、使用道具和完成全部已实现的等待输入。难度不改变现金、收入、抽卡概率、骰子分布或正式规则。

交易统一评估双方的地产与现金变化、固定赎回负担、现金储备和本人当前待付费用。主动报价围绕基础估值与综合评分生成有限价格候选，资金紧张会影响议价和候选价格；再用与接受报价相同的评分核对双方意愿。普通和困难会更重视补齐现金缺口、避免将现金耗尽，以及成交后对方领先程度和双方名次的变化。对真人的意愿以普通策略估计，仅用于判断报价是否有成交可能，不代表能预测真人接受，也不会读取对方手牌。

第一阶段调整增加核心地产惜售：交易后失去的预计租金占比越高、损失的单次租金越高，出售补偿越高；换回收入地产会抵减损失，现金紧张时降低补偿要求。提高连片权重，保留现有对手获益和排名惩罚。此补偿同时用于主动报价和收到报价的评估，不改变买地、升级估值及正式经济规则。

主动报价需满足筹补现金缺口、改善连片或预计收入、明显高收益机会之一。正常报价综合收益至少达到本局起点收入的 12% 和付出估值的 8%，并满足原有难度门槛；当前欠款筹资分别降为 2.5% 和 2%，保留抵债空间。接受报价不要求主动交易动机。以上为初始策略参数，尚需实际对局校准。

连片按棋盘上相邻且同属一人的地产评估，特殊格中断；比较交易前后两边的相邻连接和三块以上连续区域，体现补齐连片、拆散自家连片及帮助对手连片的策略影响，抵押地产折减。此值只用于 AI 决策，不写回地价、净资产或租金。交易后的排名仍按现有成本权益和真实现金计算；约定抵债不虚算成现金或排行榜增值。买卖、带现金互换和抵债均经过同一评估及原有正式交易校验。

规划通过枚举六种公平骰子结果，计算有界的落点分布与动态规划位置收益；考虑已公开的路障、移动翻倍、休息、服刑停租、租金、抵押负担及起点奖励。在收到新局面后重新评估。前瞻对后续投资、对手策略、事件和一次性状态变化采用近似估值，不是完整对局搜索，也不承诺全局最优或特定胜率。

机器人猜拳、赛马、红包、盲盒、宝箱及桥面等未知结果的选择使用独立的 `ThreadLocalRandom`，不使用游戏的正式 `RandomSource`。规划不会试抽正式骰子或事件。

## 自动操作覆盖

- 回合：掷骰、买地／放弃、升级／放弃、赎回、结束行动。
- 交易：综合双方现金压力、交易前后排名、净资产差距、连片及核心收入损失，仅为明确动机发起现金买卖或带现金补差的地产互换，接受或拒绝收到的报价；玩家债务允许协商资产抵债。每名机器人两次主动报价至少间隔一轮完整的在场玩家行动；持久化最近三十二份报价的接收人、现金、地产状态及债务上下文，相同条件不重报。另在三个完整在场玩家行动轮次内，屏蔽同一对象、相同地产买卖方向和资产状态的换价重报；产权、等级、抵押或债务上下文变化时重新评估。该限制基于已发报价，不区分接受、拒绝或取消结果，也不新增存档字段。真人收到报价后，沿用原有不限时回应规则。
- 付款：免租和减半卡先比较当前减免、支付后现金及留牌价值。留牌价值参考本局起点收入、公开对手当前租金和下一级建筑租金的折扣风险；现金充足时保留关键牌，资金不足时优先减免，支付后现金逼近安全线时降低留牌门槛。安全线取既有风险储备与当前现金 25% 的较小值；多张同类牌及满手牌时适当降低保留成本。均能达到安全线且值得使用时，优先消耗保留成本较低的牌，不只比较减免金额。保守兜底仍选择最大减免。未用卡则现金支付，或选择预计收入损失较低的地产抵押；全部抵押所得不足时优先选择整套出售或先卖房再变现，已抵押地产也可按扣除固定赎回费用后的正净额出售，避免有能力出售偿清却误申请清算。玩家债务可先报价筹款或抵债；仍不足时按现有规则申请清算。
- 内容选择：六张手牌保留、免费升级、直升满级、摧毁自家建筑、摧毁对手建筑、赌博、解控／接受休息或监禁。候选按当前产权、建筑与升级状态过滤；等待期间因业主被移出而失去全部摧毁目标时，沿用无目标结束规则，不产生损失或补偿。
- 主动道具：遥控骰子、固定／前后移动、旧原地停留、掷骰加码、路障、拆房、换位、传送、指定入狱、现金、免费升级、抢夺和赌博。防御卡与解控卡仅在原规则允许的等待点使用。
- 九类活动：赌场、赛马、轮盘对决、红包、猜拳、贪心宝箱、玻璃桥、少数派夜市、盲盒。会检查参与者、已提交名单、子轮次及可领取序号；展示阶段由原活动计时逻辑推进，活动债务复用普通付款流程。

## 调度、持久化与兼容

`RoomService.advanceBots` 每 800 毫秒检查一次，每个房间至多提交一个机器人行动。先在内存定位等待者，再在已有房间锁中依据最新局面规划；仅参与者真正需要输入时行动，等待真人或展示阶段时不强推。

机器人动作调用同一 `GameWorkflow.apply`、领域校验及效果结算，在同一事务中保存 Flowable 进度、房间和历史。提交成功后才替换内存并广播。规则拒绝会回滚候选局面、记录日志，下一次调度在新事实上下文中使用保守操作，避免将失败尝试混进已提交历史。兜底按机器人及实际等待点保存，聊天与连接导致的版本变化不清除它；保守模式跳过前瞻与资产评分，规划阶段异常也能进入兜底。数据库等基础设施错误保留正式进度，后续调度重试。

内部玩家新增 `botDifficulty`、`botTradeTurn` 和 `botTradeQuotes`，随现有 JSON 快照保存，无额外数据库表或字段迁移。没有 `botDifficulty` 的旧玩家按真人处理；新增可选动作字段为空时不改变旧命令摘要。机器人无需 WebSocket 连接，不被心跳检查改成离线，也不接任房主。服务重启后恢复机器人在线状态；恢复存档时仍等待真人房主继续，机器人席位不可被真人申请或分配。再开局保留机器人难度，重置报价记录并自动准备。

## DeepSeek 聊天与议价第一版

`BotDialogueService` 在规则策略之外加入可选的模型候选选择，`DeepSeekClient` 异步调用固定官方地址 `https://api.deepseek.com/chat/completions`。第一版只选择服务器提供的聊天话术与安全交易候选，不接收或广播模型自由生成的文字，不提供工具调用。这样聊天中的角色伪造、规则修改和虚构承诺即使影响模型选择，也不能增加操作权限、泄露手牌或执行任意资产转移。普通掷骰、买地、升级、用卡、付款及活动选择仍由原规则机器人完成。

### 环境变量

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 空 | 仅从服务端运行环境读取；为空或含非法请求头字符时关闭模型调用 |
| `DEEPSEEK_ENABLED` | `true` | 关闭时完全沿用规则机器人 |
| `DEEPSEEK_MODEL` | `deepseek-flash` | 模型名称，显式关闭思考模式 |
| `DEEPSEEK_AUDIT_PATH` | `data/deepseek-calls.jsonl` | 相对 Java 进程工作目录的分析记录文件，可设置绝对路径 |

本机 Java／宝塔进程需在启动环境设置变量；Spring 不会自动把仓库 `.env` 文件当成进程环境。Compose 已透传上述密钥、开关和模型变量，记录固定写到 `/app/data/deepseek-calls.jsonl`，通过 `bot-model-data` 命名卷保留；镜像预先为非 root 用户准备可写目录。`.env.example` 只保留空密钥占位，不包含真实 Key。修改进程环境后需重启应用生效；本机已通过进程环境注入并重启验证，未部署服务器。

接口使用非流式 JSON 模式，返回格式严格限制为 `{"optionId":"本次候选编号"}`。80 token 的单次输出上限只用于约束这个小对象，不是费用或使用额度预算。当前不设置每局、每日调用次数、累计 token 或金额上限。

### 偶尔聊天与交易议价

- 玩家通过现有聊天引用功能 `@机器人` 或引用机器人拥有的地产时，选择一名符合间隔要求的机器人回应；交易时建议同时引用具体地块并写明金额，例如 `@机器人 10000 买 @地块`。未引用具体地块时只做普通回应，不从名字猜测产权。可识别整数金额以及万／千／k 单位，金额解析只用于生成候选，不构成玩家授权。
- 租金、交易、建筑相关公开事件有小概率触发闲聊。一次事件只尝试一次；同房间模型请求至少间隔 10 秒，同机器人至少间隔 30 秒，聊天和交易共用间隔，间隔内直接沿用规则策略。允许保持沉默，机器人发言不会触发机器人互相回复。这些是防刷屏和重入约束，不是使用预算。
- 规则策略已经准备向真人报价、接受或拒绝真人正式报价时，可让模型选择安全报价、拒绝、还价建议或暂不主动报价。机器人之间的交易继续沿用规则策略。现金、地产和抵债条件均来自服务器，模型不能自填金额或地产编号。
- 报价候选复用核心地产惜售、现金安全和收益评估，主动报价仍需动机及更高门槛。非本人允许报价的阶段只能提出明确标注为“尚未成交”的意向；对收到的报价还价时，只能拒绝并建议原发起人重新报价，不能代替真人取消、修改或接受交易。

### 明确确认与履约

机器人发起报价时，正式报价、`Trade.botConfirmed` 标记、确认聊天、报价记忆和历史在原有同一事务内保存；交易保存失败时不出现承诺聊天。机器人接受已有正式报价时，资产交换与“已完成交易”的聊天同样原子提交。确认消息由服务器生成，不从模型文本推断。

“可以继续谈”只是意向；“我确认这份交易条件，正式报价已发出”才表示绑定当前正式报价。真人仍通过原交易面板确认或拒绝。确认后等待真人回应，不自动改价、撤销或重新运行模型评分；服务重启后从房间快照恢复同一报价。模型失败、超时和无关聊天不撤销承诺。真人拒绝／取消会结束对应报价，不能用聊天中的历史承诺伪造新报价。最终交换继续核对双方身份、产权、现金和债务合法性，报价仍沿用原不限时回应规则。

### 提示词攻击与异步回退

模型上下文显式构造，只包含公开资产、当前决策、参与的正式报价、最近四条真人聊天和已校验候选，不序列化完整房间或私人投影，不包含手牌、存档码、种子、会话或 API Key。昵称不参与身份判断和交易话术，金额与地块通过固定 ID 表达。聊天始终放在低信任 `user` 消息内，不进入系统提示；常见 Key／Bearer 形式遮盖，模型正文、错误正文和推理内容不写入公开聊天或分析记录。

每房间至多一个在途请求，同一交易等待点只尝试一次。调用使用异步 HTTP，不在房间锁内等待网络；普通聊天两秒、涉及议价四秒总时限，连接时限一秒。返回后由调度器重新进入房间锁：带交易条件的结果核对公开资产、决策快照及最新点名消息，无关聊天、版本递增及连接变化不使结果失效。局面改变、收到新的相关点名、暂停、恢复等待、结束或取消请求时丢弃旧建议。超时、限流、认证失败、无效／截断 JSON、未知候选均不立即重试，交易回退原规则行动，普通聊天保持沉默。迟到结果不执行。普通发言和沉默不会清除既有规则兜底标记。

### 分析记录

异步追加 JSONL，按 `requestId` 关联四个阶段：`request` 记录房间、本局、机器人、事件、回合、快照版本、时限与安全候选；`response` 记录模型、固定状态、耗时、候选编号及供应商返回的输入／输出／总量／缓存 token；`decision` 区分选择、过时丢弃及回退；`execution` 区分实际提交、沉默或提交失败。使用房间和快照版本可回查现有历史，无需记录原始聊天、完整提示词或模型响应。

超时和取消可能没有供应商 usage，此时记为空对象，不能按零费用统计。记录不是账单，当前不基于它限制使用。文件写入失败只记录固定警告，不阻塞游戏或误回滚已提交交易；第一版不新增数据库表及分析接口。
