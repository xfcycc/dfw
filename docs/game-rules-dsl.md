# 回合阶段与事件规则配置

服务启动时加载四份行为分类文件，合并编译为唯一不可变 `RuleSet`，直接注入领域服务。没有规则版本号、摘要绑定、旧规则文件或旧引擎路径。经济与地区分别使用独立的 `economy.json`、`map-regions.json`，见 [金额与地区配置](game-configuration.md)；HTTP/WebSocket 沿用原信封，新增费用确认及可选抵债字段见 [联机协议](realtime-protocol.md#强制费用与资产抵债)。

## 分类加载与配置修改

| Spring 配置 | 环境变量 | 默认 classpath 文件 | 根结构 |
| --- | --- | --- | --- |
| `game.rules.chance-events` | `GAME_RULES_CHANCE_EVENTS` | `game-rules/chance-events.json` | `events`、`passiveRules`、`content` |
| `game.rules.fortune-events` | `GAME_RULES_FORTUNE_EVENTS` | `game-rules/fortune-events.json` | `events`、`content` |
| `game.rules.card-events` | `GAME_RULES_CARD_EVENTS` | `game-rules/card-events.json` | `cards`、`content` |
| `game.rules.turn-rules` | `GAME_RULES_TURN_RULES` | `game-rules/turn-rules.json` | `stages` |

`GameRulesConfig` 分别读取四种独立根结构，严格拒绝未知字段、重复业务 ID、未知处理器、非法阶段引用和参数，再编译为不可变集合。每文件最多 256 KiB，不支持资源模式或在游戏中热替换。事件 ID 在机会和财富池之间也不能重复。

修改配置后重启，所有进行中对局后续抽取和阶段推进使用当前配置；完整新手牌按取得时冻结的参数和皮肤使用，原六种无皮肤手牌仍按兼容 DSL 使用。已经入队的具体效果、全体扣款固定目标与金额、原 `pending` 债务、灾害匹配订阅及已提交样本继续按保存的进度执行，不重新解析、匹配或抽样。恢复时刷新公开扩展机会说明。结构或流程任务不一致时拒绝继续，不迁移旧存档或重建流程。

新局另保存本局经济快照和固定现金步骤的最终金额。`PAY_FEE`、`CHARGE_ALL`、`GRANT_MONEY` 的常量金额默认乘经济倍率，金额引用使用已计算的实际值；`<规则ID>.<从0开始的步骤序号>.amount` 可以覆盖最终金额。MOVE 等非现金效果不乘倍率，比例补偿也由实际建筑损失计算，不二次放大。现金步骤日志可使用 `{effect.amount}`，避免文案仍显示基准金额。进行中对局勿修改同一规则的 ID、步骤顺序或效果结构；经济快照不等于完整行为规则版本冻结。

2026-10-13 新增 `content` 分层抽取，已接入全部 342 条素材、十二类道具和确认的事件机制，详见 [完整内容接入](game-content-runtime.md)。三份内容配置均须提供 `content`，旧外部规则文件需要按该结构补齐。本文的 `events` 和六卡 `cards` DSL 保留旧手牌、自动阶段与已入队效果的兼容能力，不再决定新事件和新手牌的抽取概率；不要将 `weight` 混入旧 DSL 层。

例如将机会配置替换为外部文件：

```sh
GAME_RULES_CHANCE_EVENTS=file:/srv/dfw/rules/chance-events.json npm start
```

也可使用 `--game.rules.chance-events=file:/srv/dfw/rules/chance-events.json` 等 Java 参数；数据源仍由 `DB_*` 或显式 `spring.datasource.*` 配置提供。规则定义及运行时不再保存规则版本，但房间 `version`、命令 `expectedVersion`、命令 ID 和业务事件 ID 继续用于并发、去重和事实关联。

## 配置回合阶段

默认阶段顺序为：

```text
TURN_START 自动阶段
→ before_roll 行动窗口（pre_roll）
→ BEFORE_DICE 自动阶段
→ ROLL
→ AFTER_DICE 自动阶段
→ MOVEMENT
→ LANDING
→ manage 行动窗口（manage）
→ TURN_END 自动阶段
→ END_TURN
```

| handler | 行为 | 配置字段 |
| --- | --- | --- |
| `AUTO_HOOK` | 进入一次时解析并入队步骤 | `id`、`hook`、`steps` |
| `ACTION_WINDOW` | 接受原命令并等待退出结果 | `id`、`phase`、`actions`、`exitOn` |
| `ROLL` | 使用已接受的随机或替代骰子结果 | `id` |
| `MOVEMENT` | 执行一次阶段移动 | `id` |
| `LANDING` | 执行落点及后续事件结算 | `id` |
| `END_TURN` | 切换下一行动者 | `id` |

行动窗口的 `phase` 使用前端已有的 `pre_roll` 或 `manage`。`actions` 使用 `roll`、`card`、`tradeOffer`、`sellBuilding`、`mortgage`、`redeem`、`sellLand`、`endTurn`；`exitOn` 可以引用允许命令，或在出牌窗口使用 `replace_roll`。落点的买地、升级、租金、偿债选择仍使用原 `pending`，不会被窗口配置绕过。

地图大小使用大厅生命周期命令 `setMapSize`，只允许房主开局前设置，不属于这些回合行动窗口，也不能通过配置在进行中重建地图。大小随房间保存，四份行为文件不管理地图尺寸。机会与财富新确认的机制概率见 [评审主稿](game-content-design.md#6-财富与机会的确认规则)，已接入新的分层内容目录。

静态校验要求首阶段为 `TURN_START`，唯一的 `ROLL`、`MOVEMENT`、`LANDING`、`END_TURN` 按依赖顺序排列，最后为 `END_TURN`，掷骰与回合结束窗口能到达对应自动段。可以插入自动阶段及配置步骤，无需修改 BPMN。阶段 handler 提供能力，`hook` 是当前阶段的发生名称；阶段 hook 的通用订阅尚未实现，当前限定订阅只响应实际灾害建筑损失。

例如在 `ROLL` 之后加入自动阶段：

```json
{
  "id": "after_dice_notice",
  "handler": "AUTO_HOOK",
  "hook": "AFTER_DICE_NOTICE",
  "steps": [
    { "op": "APPLY_EFFECT", "type": "LOG", "message": "{actor.name} 的骰子已确定为 {turn.dice} 点" }
  ]
}
```

回合位置、回合编号、窗口退出结果、掷骰来源和移动步数保存在 `Room.runtime`。自动阶段先保存下一位置，再结算步骤；等待或重启不会重做已提交阶段。按原玩法，监狱/休息跳过在 `TURN_START` 执行，被跳过的回合不进入后续阶段。离线行动者暂停，重新认证后通过通用流程继续。

## 道具定义

每张道具定义 `id`、`activation`、`stages`、`countsAsActive`、`checks`、`steps`。`id` 对应前端既有的卡牌 kind；`ACTIVE` 为主动出牌，`RENT` 在 `rent_choice` 阶段发动且不占主动次数。租金防御组合必须先使用 `WAIVE_RENT` 解决本次费用。

遥控骰子的实际配置结构如下：

```json
{
  "id": "remote",
  "activation": "ACTIVE",
  "stages": ["before_roll"],
  "countsAsActive": true,
  "checks": [
    {
      "condition": {
        "op": "ALL",
        "args": [
          { "op": "GTE", "left": { "ref": "action.point" }, "right": 1 },
          { "op": "LTE", "left": { "ref": "action.point" }, "right": 6 }
        ]
      },
      "error": "请选择 1～6 点"
    }
  ],
  "steps": [
    {
      "op": "APPLY_EFFECT",
      "type": "REPLACE_ROLL",
      "params": { "amount": { "ref": "action.point" } },
      "message": "{actor.name} 本次移动 {action.point} 格"
    }
  ]
}
```

`REPLACE_ROLL` 只设置点数和替代结果，实际移动与落点由阶段执行；含该原语的卡牌不能再配置 `MOVE` 或 `SETTLE_TILE`。停留同样使用 `REPLACE_ROLL`，`amount` 为零。换位、路障及拆房不退出掷骰窗口，仍需随后掷骰。

所有条件和参数在扣卡前检查并解析。基础处理器在生效时复核地产、建筑或玩家仍可用，配置不能绕过已有认证、回合归属、交易身份或资产归属校验。

## 受控 DSL

当前支持有序 `APPLY_EFFECT`，步骤不是任意函数调用。

| 效果类型 | 参数 | 行为 |
| --- | --- | --- |
| `REPLACE_ROLL` | `amount` | 设置 0～6 点的替代结果 |
| `PLACE_BARRIER` | `tileId` | 设置地块路障 |
| `DEMOLISH` | `tileId` | 建筑降低一级，无退款 |
| `SWAP_POSITION` | `targetId` | 交换与目标的位置，不结算落点 |
| `WAIVE_RENT` | 无 | 解决本次租金选择 |
| `MOVE` | `amount` | 有符号移动，一步参数范围为 −40～40 |
| `SETTLE_TILE` | 无 | 结算当前地块 |
| `PAY_FEE` | `amount`，可选 `targetId`、`tileId` | 非负费用，未指定收款人为银行；正数保存支付选择，零直接完成 |
| `CHARGE_ALL` | `amount` | 按发动时座位顺序固定未破产目标，逐人确认银行费用，整批完成后判胜 |
| `ADD_STATUS` | `statusId: "TRAP_IMMUNITY"`、`amount: 3` | 立即生效，三个后续个人回合结束后到期，重复刷新 |
| `DESTROY_BUILDINGS` | `tileId` 或 `selector: "RANDOM_BUILT_PROPERTY"` | 指定或随机一块地产全部建筑，保存实际灾害损失后触发当前补偿订阅 |
| `DRAW_CARDS` | `amount` | 发放 0～32 张私人随机道具，公开日志仅记录私人补给 |
| `SKIP_TURN` | `amount` | 设置 0～32 次后续休息，普通休息不等同监禁 |
| `GRANT_MONEY` | `amount` | 给作用玩家发放非负银行奖励；内部补偿也复用此处理器 |
| `LOG` | `message` | 写入公开日志，遵循原日志保留方式 |

表达式支持常量、`{"ref":"路径"}`、`ALL`、`ANY`、`NOT`、`EQ`、`NE`、`GT`、`GTE`、`LT`、`LTE`。`ALL`/`ANY` 使用 `args`，`NOT` 使用 `value`，比较使用 `left`/`right`。数值按数值比较，不把字符串强转为数字；参数必须解析为整数。不存在的目标返回空字段或 `exists=false`，数值比较返回 false，不因缺少可选目标而抛出空指针。

| 上下文 | 允许引用 |
| --- | --- |
| `actor` | `id`、`name`、`cash`、`position` |
| `action` | `point`、`tileId`、`playerId` |
| `targetTile` | `exists`、`id`、`type`、`ownerId`、`level`、`barrier`、`forwardDistance` |
| `targetPlayer` | `exists`、`id`、`bankrupt`、`jailed` |
| `turn` | `phase`、`activeCardUsed`、`dice` |

`message` 使用相同白名单的 `{actor.name}` 等占位符；不能访问手牌、会话令牌或流程对象。自动阶段只允许 `actor`/`turn` 引用，且骰子引用必须位于 `ROLL` 之后。没有 Spring EL、反射、脚本、SQL 或网络访问能力。

每文件最多 256 KiB，阶段/道具/组合数量及表达式深度有限；效果和阶段自动推进均有工作量上限。配置非法时拒绝启动，动态输入或处理器失败时回滚当前短事务，返回原错误协议。

组合遇到买地、升级、租金或偿债选择时，`effectsWaiting` 和剩余效果持久化。解决当前选择的效果先于暂停组合，选择完成后继续。清算或房主管理导致回合换人时，旧回合的单玩家剩余组合取消。`CHARGE_ALL` 在 `globalEvent` 中保存固定目标、下一目标索引、金额和返回阶段；当前债务保存在原 `pending`，解决后继续队列。批次内淘汰不换回合、不提前判胜，全部目标处理完才判胜或切换已淘汰的行动者。目标被房主移出时清除其待偿债，后续已淘汰目标跳过。

费用现为动态等待流程：现金足够也先选择付款方式，抵押、卖房或卖地筹足后不自动支付。玩家债务允许插入资产抵债或第三方融资报价，系统费用由本人选择地产向银行抵押，不在此窗口向玩家报价。内部 `SETTLE_PAYMENT`、`DECLARE_BANKRUPTCY` 与偿债中的 `OPEN_TRADE` / `ACCEPT_TRADE` / `CLOSE_TRADE` 使用 `resumesDecision` 插在暂停的兄弟效果之前，保持父阶段及债务关联；报价拒绝或主动取消只返回原费用。所有玩法选择、偿债和报价均不限时，相关玩家离线时保留待选，重连后继续。两项内部费用处理器不开放给规则 JSON，配置入口仍为 `PAY_FEE` / `CHARGE_ALL`。整体抵押、部分抵扣和清算出口详见 [内容设计](game-content-design.md#21-强制费用资产抵债与整体抵押)。

## 机会事件与持续状态

机会和财富文件原 `events` 是保留的兼容自动组合，每项提供唯一 `id`、非空 `steps`，`description` 可省略。此前简化机会九种结果：获得 300、支付 300、前进三格、后退三格、休息一次、私人补给一张、全体扣款 300、三回合陷阱免疫和随机建筑灾害，各为 1/9。此前简化财富六种结果：获得 300/500/800/1000、私人补给一张/两张，各为 1/6。当前实际抽取使用 `content`，概率见内容主稿；每回合一次抽取限制继续有效。移动事件配置 `MOVE` 后接 `SETTLE_TILE`，仍结算经过起点、路障和落点，但不能再抽第二个机会/财富事件。

事件可使用 `CHARGE_ALL`、`ADD_STATUS`、`DESTROY_BUILDINGS`、`GRANT_MONEY`、`DRAW_CARDS`、`SKIP_TURN`、`PAY_FEE`、`MOVE`、`SETTLE_TILE`、`LOG`；自动引用仅限 `actor`/`turn`。默认只为三项扩展机会填写 `description`，继续通过 `chanceEventDescriptions` 展示这三项说明，不新增前端必填字段。基础六项文案和私人补给隐私保持原样。

```json
{
  "id": "global_levy",
  "description": "全体各向银行支付 300",
  "steps": [{ "op": "APPLY_EFFECT", "type": "CHARGE_ALL", "params": { "amount": 300 } }]
}
```

指定地块的基础效果示例（`tileId` 必须是当前地图有效地产索引）：

```json
{
  "op": "APPLY_EFFECT",
  "type": "DESTROY_BUILDINGS",
  "params": { "tileId": 1 }
}
```

龙卷风使用随机有建筑地产选择器，允许选中自己的地产；产权、抵押和路障保留。只对实际摧毁的建筑级数计算造价损失，无建筑不抽补偿样本、不赔付。单地块对应一个受损业主，以 0～99 样本 `< 30` 判定补偿，赔付为损失的 50% 向下取整。目标、产权人、级数、损失、样本和赔付作为 `lastDisaster` 保存在内部运行时；这是最近一次实际损失记录，不是长期事件审计。未实现建筑保护状态，不将陷阱免疫误当灾害保护。

`Player.statuses` 保存状态类型、来源效果、施放/刷新回合和剩余后续个人回合。期限仅在持有人结束回合时扣减，施放当回合不扣，跳过行动照常计数；第三个后续个人回合结束时移除。路障标签按 `TRAP` 判定免疫，免疫时继续移动且保留路障；租金、罚款、监禁和灾害不受影响。重复获取刷新为三回合，破产或再开局清除状态。

费用权限来自 `pending.playerId`，Flowable 等待者和离线暂停跟随当前付款人；玩家报价时等待接收人，结束后返回付款人。无关玩家离线不阻塞当前费用。前端复用资产管理弹框和经营命令，增加手动付款与抵债报价，`turnIndex` 仍表示原回合持有人。公开可选字段保留 `chanceEventDescriptions` 和 `players[].trapImmunityTurns`，费用新增 `pending.id`，抵押新增 `board[].mortgageBase`；内部队列、目标游标、随机样本和流程标识不对外发送。原命令保留，但完整操作新支付选择需刷新前端。

## 实际损失与独立补偿订阅

随机补偿位于机会文件的 `passiveRules`：

```json
{
  "passiveRules": [
    {
      "id": "government_disaster_compensation",
      "trigger": "BUILDINGS_DESTROYED",
      "tag": "DISASTER",
      "probability": 30,
      "compensationPercent": 50
    }
  ]
}
```

当前订阅只支持 `BUILDINGS_DESTROYED` + `DISASTER`，不是任意事件表达式。ID 唯一，订阅最多 32 项，概率及比例为 0～100 的整数。列表顺序是执行顺序；每条匹配订阅对同一实际损失独立抽样一次。默认仅一条订阅，赔付口径不变。

摧毁处理器只对实际损失创建事实，保存事件 ID、来源效果、受损时业主、地块、被毁级数和损失。普通拆房、卖房及空建筑不生成该灾害事实。匹配订阅及概率/比例在损失发生时固定，保存为内部 `RANDOM_COMPENSATION` 子效果；成功后再插入 `GRANT_MONEY`，先完成赔付再执行下一项兄弟效果。订阅读取当前内存规则集，不逐目标访问数据库。

匹配、抽样、赔付和队列同房间候选及 Flowable 一起提交或回滚。已提交的事实保存各订阅样本、应赔、实赔及支付完成标记，恢复不重新匹配或抽样。按受损时业主支付，执行时已移出或破产则跳过；补偿不会产生新的建筑损失。当前仍只保存最近一项 `lastDisaster`，不宣称已有完整事件总线或长期结构化事件存储。

内联补偿参数和处理分支已删除。`DESTROY_BUILDINGS` 只接受目标参数，内部订阅原语不开放客户端命令，公开协议无需新增字段。

## 当前实现边界与验证

四类首期能力已通过受控 `APPLY_EFFECT` 和专用全体扣款执行帧接入，不增加 BPMN 节点。完整 `FOR_EACH`、任意嵌套执行帧、通用随机分支、建筑保护、多地块损失聚合、通用被动事件总线、长期结构化事件审计仍未实现。当前已提供限定的实际灾害损失订阅，补偿从摧毁处理器分离；任意事实条件、通用随机分支及完整被动 DSL 仍未实现，不能将完整架构设计示例当成已支持的 DSL。
