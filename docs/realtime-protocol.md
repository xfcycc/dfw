# 原生 WebSocket 联机协议

HTTP 与 `/ws` 共用端口 3001。开发由 Vite 代理，生产使用 HTTPS / WSS。没有 Socket.IO、STOMP 或长轮询。

消息格式：

```json
{"type":"game:command","requestId":"浏览器关联标识","payload":{"id":"UUID","expectedVersion":8,"action":{"type":"roll"}}}
```

`requestId` 只关联网络响应；`payload.id` 才是持久化的业务去重标识。服务端公共状态版本以已提交结果为准。

| 方向 | type | payload 与用途 |
| --- | --- | --- |
| 客户端 → 服务端 | `session:authenticate` | `{token}`，连接首条消息，原始令牌不放 URL |
| 服务端 → 客户端 | `session:authenticated` | `{ok:true}`，之后允许同步或发送命令 |
| 客户端 → 服务端 | `room:sync` | 无载荷，申请本角色全量状态 |
| 服务端 → 客户端 | `room:snapshot` | `PublicRoomState`，所有认证角色可见 |
| 服务端 → 玩家 | `player:private` | `PrivatePlayerState`，只给本人有效连接 |
| 客户端 → 服务端 | `game:command` | `GameCommand`，必须附请求关联标识才能匹配回执 |
| 服务端 → 客户端 | `command:result` | `CommandResult`，带原 `requestId` |
| 服务端 → 客户端 | `room:error` | 认证、同步或消息格式失败的 `CommandResult` |
| 服务端 → 旧连接 | `session:replaced` | 无私人载荷，旧客户端停止自动重连 |
| 客户端 → 服务端 | `heartbeat` | 无载荷，20 秒一次 |
| 服务端 → 客户端 | `heartbeat:ack` | 无业务载荷，用于连接活跃检查 |

认证前不发送任何房间或私人状态；5 秒未认证关闭连接。无效身份返回错误后关闭连接。WebSocket 文本消息上限 64 KiB。服务端连续 60 秒未收到消息关闭连接。

客户端连续 60 秒未收到服务消息重连，重连间隔从 700 毫秒递增到最多 4 秒。每次重新发送认证，接收全量状态后恢复页面；不自动重发掷骰、交易等业务命令。命令等待 8 秒，超时显示同步提示并申请 `room:sync` 核对已提交结果。

`STALE_VERSION` 拒绝旧版本并同步最新状态。相同命令 ID 重放优先返回已保存回执，操作者须与原回执相同。新回执保存已清理 action 的规范化 SHA-256（对象字段按名称排序，列表保持原顺序），同 ID 同 action 即使预期版本已过期仍返回原结果；同 ID 改 action 返回既有 `INVALID_INPUT` 错误码。网络 `requestId` 和 `expectedVersion` 不参与业务摘要。旧回执没有摘要时保留原重放行为，无法追溯校验其原请求。摘要仅保存在回执存储 JSON，不加入 `CommandResult` 或公开状态。`FORBIDDEN` 用于观战或被替换连接操作；`INVALID_INPUT` 用于原接口边界的参数错误；`SAVE_FAILED` 不包含数据库细节。

公开玩家新增 `cardCount`，只包含 `player.hand.size()` 的持有数量，不包含卡面或超限待选候选牌。玩家和观众均收到相同数量，旧服务端和已有历史快照可缺省，前端显示为 `—`。观战不接收具体手牌，公开日志不包含补给卡型；起点按本局人数补给：2 人局 1 张，3 人及以上对局 2 张（含已淘汰玩家）。待确认报价对象仅交易双方收到，公共状态保留 `tradePending` 标志；发起报价时将双方、各自现金和地产明细写入公开记录，所有玩家和观众均可查看。同意、拒绝和主动取消包含回应主体及原报价，成交记录说明资金与地产方向。

玩家形象通过原操作入口发送 `{ type: 'setAvatar', avatarId }`，仅修改当前会话本人形象，支持 20 种形象，完整标识见 `src/shared/avatars.ts` 与后端 `PlayerAvatars.IDS`，其中新增 `pikachu`、`eevee`、`ninja`、`caixukun`；展示名称使用角色名字，原标识保留以兼容存档。公开玩家的可选 `avatarId` 缺省为 `explorer`。最近公开日志包含可选 `mentions`（玩家标识、当时姓名、颜色）。`POST /api/rooms/logs` 输入 `token` 与可选序号 `cursor`，认证当前房间玩家或观战会话后返回本局公开日志分页，沿用 `HistoryPage`，每页至多 50 条；不接收房间或对局标识，不返回私人内部明细。公开历史条目可包含 `logId` 和 `mentions`，用于与实时快照去重及姓名标记，旧条目仍保持原文。

私人状态增加可选 `tradeRejection`，保存本人发起的最近报价被对方拒绝时的说明，仅发送给发起人；旧快照缺省为空。前端在收到新的拒绝结果时展示轻提示，并在交易编辑表单保留说明。成功发出新报价或重置对局时清除；主动取消和成交不产生拒绝提示，重复同步与首次重连同步不重复弹出旧结果。

## 卡面动画的兼容扩展

公开快照新增可选 `playedCard` 与 `playedCardPlayerId`，仅在道具实际消耗时更新，供所有玩家和观战页播放出牌动画。卡面只包含已使用道具的身份、类别、名称、稀有度、描述、台词和实际效果，不包含剩余手牌、内部数值参数或抢夺得到的卡面。免费升级取消、没有合法目标或抢夺空手对手等保留卡牌的情况不更新该字段；旧快照缺省按无新出牌处理。

客户端对递增版本中的新公开事件、已使用道具和本人新增手牌排队揭卡，先展示出牌再展示该次操作带来的事件与补给。首次进入和重连建立展示基线；关闭动画只关闭本地卡面，不提交游戏操作或延迟服务端结算。私人事件和新增手牌继续仅向持有人展示。

`motion` 兼容扩展可选 `segments`，按单次结算的实际执行顺序包含全部移动片段。每段保留 `id`、`playerId`、`from`、`path`，以及可选 `dice`（只有掷骰移动填写）、`event`（本段落点抽出的公开事件）、`beforeEvent`（触发本段移动的公开事件，供跨选择恢复接续）。原 `motion.id/playerId/from/path` 继续表示最后一段，旧客户端不受影响；旧快照缺少或具有空 `segments` 时，新客户端沿用单路径播放。

客户端先播放第一段并在落地后揭示 `event`，收起卡面后继续事件移动；若先因手牌整理等选择暂停，后续快照通过 `beforeEvent` 保留触发卡面，相同事件身份只揭示一次。各段只播放自身骰子信息，最终落地后同步现金、手牌、记录与待办。片段仅包含公开事件，私人补给不写入 `event/beforeEvent`；服务端收集器只作用于本次候选房间，不序列化，也不累积上次提交的路径。重连及恢复只显示已提交局面，不补播历史片段。

## 全图事件的兼容扩展

分类规则集保留原信封、`expectedVersion`、`phase` 与 `pending`。全体扣款等待费用结算时，`turnIndex` 仍是原回合玩家，`pending.playerId` 是当前付款人。前端按后者启用资产管理与付款；报价等待时仅允许报价双方按原权限取消或回应，不能据此操作其他人的资产。离线暂停跟随付款人及报价接收人，Flowable 报价等待者为接收人，报价结束后返回付款人。

公开快照继续保留可省略的 `chanceEventDescriptions: string[]` 和 `players[].trapImmunityTurns: number`。前者为当前扩展机会玩法说明，恢复时刷新，后者为剩余后续个人回合数（零表示无状态）。旧快照缺省按空列表和零处理。内部全图帧、队列、随机补偿样本、状态来源和流程标识不进入公开投影。旧客户端命令仍兼容，新局跨玩家偿债需刷新到支持 `pending.playerId` 的前端。

实际灾害事件、补偿订阅、随机样本及支付标记仅在服务端内部使用；相同命令和快照协议继续有效。

## 经济、地区与资产榜扩展

公开快照新增 `economy: { moneyMultiplier, rentBasePercent, fixedAmounts }`，均为公开经济配置；新局保存实际金额及基础租金百分比，默认比例为 25。已有对局使用保存的比例；旧同格式快照缺少 `economy` 时按一倍基准，缺少 `rentBasePercent` 时保留原 10% 租金。客户端展示建造、租金、卖出金额必须使用当前房间的参数，不能重复乘倍率；租金先按比例计算基础整数金额，再乘等级倍率，固定金额覆盖优先。`board[].regionId`、`regionName` 是可选命名元数据，旧地图按 `district` 显示原街区名，事件暂不按地区筛选。

`players[].netWorth` 为整数成本净资产，`assetRank` 为并列名次（已破产为 null）。所有玩家和观众收到相同数值。已抵押地产按 `max(0, 当前土地建筑成本 - 固定赎回费用)` 计权益；榜单不包含私人手牌估值。排名事件开始时从并列目标随机锁定一人，保存到内容结果，不因奖励后榜单变化重新选择。

公开房间增加可选 `mapSize: small | medium | large`，缺省为大。房主在大厅通过 `setMapSize` 命令与 `action.mapSize` 设置，新局分别按 `16＋人数×4／6／8` 生成，支持 24–64 格。开始后禁止修改，再开沿用；其他玩家和观众只读同一公开设置。34／46 格为矩形闭环。动作中的地产 ID 协议上限为 63，领域层继续核对当前实际棋盘长度、产权和合法目标，不因协议范围变大放宽这些权限。

新设置命令仍使用原 `expectedVersion`、命令 ID、房间锁和事务提交。非设置操作的空 `mapSize` 不参与 action 摘要，保持已有回执兼容；设置操作的具体大小参与摘要校验。

## 强制费用与资产抵债

所有正数 `PAY_FEE` 和全体费用目标都创建支付选择，不因现金足够、抵押后筹足或银行估值不足自动扣款/清算。租金使用原 `rent`，其他费用使用原 `debt`；金额零直接完成。`pending.amount` 表示尚待支付余额，新增可选 `pending.id` 标识具体债务。旧待选缺少 ID 时，首次偿债报价由服务端补齐；决策键仍沿用原字段，未增加 ID 以改变既有任务关联。

| 命令 | 参数与行为 |
| --- | --- |
| `payDebt` | 无额外参数；当前付款人确认用现金付清余额，不足时拒绝 |
| `rentDecision` | 原 `useCard` 保留；`false` 确认现金付租，`true` 使用原免租卡 |
| `sellBuilding` / `mortgage` / `sellLand` | 原 `tileId`；可以在租金或费用等待中变现，筹足仍需手动支付 |
| `tradeOffer` | 原参数加可选整数 `debtCredit`，省略或零为普通交换；仅玩家债务允许插入报价，系统费用不允许 |
| `tradeRespond` / `tradeCancel` | 原参数与权限；拒绝或主动取消后保留费用，接受后原子交换并抵扣 |
| `declareBankruptcy` | 无额外参数；债务人主动清算，现金加银行可变现资产足够时拒绝；系统费用须先自行抵押可用地产 |

`trade.debtId` 由服务端关联当前待支付事项，不接受客户端指定。`debtCredit` 必须非负、不超过剩余欠款，正数只允许向债权人提供至少一块地产；向第三人出售资产时必须为零。抵债金额由双方协商，不限于银行估值，对应部分不转移现金；可抵清或部分抵扣继续等待。报价中的现金仍为交易对价，余额只减少 `debtCredit`，剩余费用另用 `payDebt` 确认支付。报价发起、同意、拒绝及主动取消均进入公开日志，包含双方、现金、地产编号、建筑等级及抵押赎回费用；关联债务同时说明付款人、费用类别、收款方、当前欠款及约定抵扣。实际成交后记录抵扣金额、剩余余额和是否结清；拒绝、取消标明未成交。房租待付、放弃付款防御、卡牌减免和现金支付同样记录主体、费用及收款方，观众通过原公开快照与本局记录分页查看；不公开原始操作、内部报价标识或未使用的手牌。

棋盘新增可选 `board[].mortgageBase`：整体抵押时的土地加建筑成本估值。抵押取得其 50%，赎回付其 55%；旧已抵押地产缺省按土地价计算。建筑保留、停止收租，抵押建筑不可单独卖出，赎回基数不随拆房变化并随产权转移。租金和费用等待中禁止赎回。全体批次仍保存目标与下一目标，逐人确认完成后继续。

买地、付费／免费升级、抵押、赎回、出售建筑和土地均通过原 `log` 类型保存公开记录，包含操作主体、地块名称与编号、实际支付／返款金额和操作后现金余额。升级及出售建筑说明前后等级；抵押说明取得现金、固定赎回费用、保留建筑及暂停收租，赎回记录清除抵押基数前的实际费用及恢复收租；出售已抵押土地明确返款为零，并记录地产恢复待购入。金额沿用本局实际经济配置和原业务规则，玩家与观众可在实时及完整历史中查看。

命令摘要在 `debtCredit` 省略或零时移除该新键，保持已有回执摘要兼容；正数参与去重校验。金额和上下文仍由领域校验，继续使用房间锁、预期版本和同事务快照/回执。玩法选择、整段偿债和单份报价均不限时，报价保留到主动接受、拒绝或取消；相关玩家离线时保留待选，重连继续。系统费用确认清算前须自行抵押可用地产，且现金仍不足。

旧报价字段 `remainingMs` / `runningSince` 仅为协议与快照兼容保留，服务端刷新或恢复时分别清零、置空，不参与到期判定。旧存档中的报价即使剩余时间已为零也不会自动取消。前端移除倒计时计算与提示；网络认证、心跳检测和请求等待超时继续使用原口径，只管理连接或查询已提交结果，不自动替玩家完成游戏选择。

本轮仅完成后端编译、前端类型检查和差异静态检查，未做真实联机、重连或重启验收。旧客户端指令保留，但旧界面可能无法在新的租金选择中管理资产或确认一般费用，须刷新前端后使用新流程。

## 完整内容和私人选择扩展

分层内容接入保留原信封与公共阶段。公开 `event` 只包含公开事件的卡面及实际参数；随机／定向补给的整张卡面不给其他玩家或观众。`eventPlayerId` 为触发者，排名目标在卡面 `targetId` 中保存。`upgradedTiles` 显示本回合已升级地产，免费升级也计入。`players[].nextPaymentWaiver`、`nextRentDouble` 为公开的一次性状态。

私人状态新增 `event`（本人获得的补给事件）、`notice`／`noticeText`（最近私人结果）、`choice`（本人当前选择）。完整手牌保存 `kind`、皮肤身份、名称、稀有度、素材类型、台词、描述、实际参数与效果。新抽取结果的 `rarity` 扩展为 R／SR／SSR／UR，表示实际影响等级；道具 `kind=gamble` 复用现有 `choice.type=gamble`。有 `choice.cardId` 时表示风险手牌，确认下注才消费卡与主动次数，取消保留；确认后的开奖样本存入已使用卡快照。`choice` 仅给选择者，包含身份、类型、合法地产或本人超限候选牌；不公开父效果队列与恢复位置。公开 `pending.type=choice` 只说明实际选择者，不包含具体选择类型或卡牌数量。

`contentDecision` 带 `decisionId`，按窗口附确认／放弃的 `accept`、自家地产 `tileId`、解控 `cardId` 或恰好六个 `keepCardIds`。不一致或过期的选择拒绝，相关玩家离线保持等待。`paymentDefense` 可附 `decisionId` 和 `cardId`，省略卡代表放弃；本笔至多选择一次。`pending.originalAmount` 为翻倍后、防御前费用，`defenseResolved` 为已选择事实；未选择防御前不允许筹款、抵债或支付，自动免单则直接继续。旧 `rentDecision` 仍可免租或确认租金，已经放弃防御后不能再用免租。

选择任务的决策键增加该私人选择的唯一 ID；原买地和费用键结构保持，恢复仍严格校验原任务绑定。旧版已经进入支付／资产协商的余额保留，加载后视为已经经过该笔防御入口，不允许在已有部分抵债后再减半。新增操作字段为空时不加入摘要，原命令回执继续兼容。完整协议及保存边界见 [内容运行说明](game-content-runtime.md)。


## 房间聊天

新增兼容命令 `chat`：`{ type: "chat", message: "正文" }`，使用原命令标识、版本校验、玩家身份、幂等回执和房间事务。正文为 1～300 字的非空字符串，发送者由当前会话确定，不能指定或伪造发送者。玩家可在其他人的回合、等待报价或暂停时聊天；观战、被替换连接及等待继续的恢复房间不能发送。聊天不消耗卡牌、不改变阶段、不完成 Flowable 中的行动任务。

聊天以 `chat` 类型写入原公开日志与历史表，无数据库迁移；公开快照 `logs[].type` 是兼容的可选字段。`POST /api/rooms/logs` 的公开记录筛选包含聊天并返回其日志标识和玩家引用，实时记录可去重并在重连后恢复。历史支持 `type=chat` 筛选；聊天正文与城市事件在实时区按时间正序展示，最新在底部，历史保持倒序查阅。
