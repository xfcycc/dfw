# 原生 WebSocket 联机协议

HTTP 与 `/ws` 共用端口 3001。开发由 Vite 代理，生产使用 HTTPS / WSS。没有 Socket.IO、STOMP 或长轮询。

消息格式：

```json
{"type":"game:command","requestId":"浏览器关联标识","payload":{"id":"UUID","expectedVersion":8,"action":{"type":"roll"}}}
```

`requestId` 只关联网络响应；`payload.id` 才是持久化的业务去重标识。服务端公共状态版本以已提交结果为准。

| 方向 | type | payload 与用途 |
| --- | --- | --- |
| 客户端 → 服务端 | `session:authenticate` | `{token}`，连接首条消息，原始令牌不放 URL |
| 服务端 → 客户端 | `session:authenticated` | `{ok:true}`，之后允许同步或发送命令 |
| 客户端 → 服务端 | `room:sync` | 无载荷，申请本角色全量状态 |
| 服务端 → 客户端 | `room:snapshot` | `PublicRoomState`，所有认证角色可见 |
| 服务端 → 玩家 | `player:private` | `PrivatePlayerState`，只给本人有效连接 |
| 客户端 → 服务端 | `game:command` | `GameCommand`，必须附请求关联标识才能匹配回执 |
| 服务端 → 客户端 | `command:result` | `CommandResult`，带原 `requestId` |
| 服务端 → 客户端 | `room:error` | 认证、同步或消息格式失败的 `CommandResult` |
| 服务端 → 旧连接 | `session:replaced` | 无私人载荷，旧客户端停止自动重连 |
| 客户端 → 服务端 | `heartbeat` | 无载荷，20 秒一次 |
| 服务端 → 客户端 | `heartbeat:ack` | 无业务载荷，用于连接活跃检查 |

认证前不发送任何房间或私人状态；5 秒未认证关闭连接。无效身份返回错误后关闭连接。WebSocket 文本消息上限 64 KiB。服务端连续 60 秒未收到消息关闭连接。

客户端连续 60 秒未收到服务消息重连，重连间隔从 700 毫秒递增到最多 4 秒。每次重新发送认证，接收全量状态后恢复页面；不自动重发掷骰、交易等业务命令。命令等待 8 秒，超时显示同步提示并申请 `room:sync` 核对已提交结果。

`STALE_VERSION` 拒绝旧版本并同步最新状态。相同命令 ID 重放优先返回已保存回执，操作者须与原回执相同。新回执保存已清理 action 的规范化 SHA-256（对象字段按名称排序，列表保持原顺序），同 ID 同 action 即使预期版本已过期仍返回原结果；同 ID 改 action 返回既有 `INVALID_INPUT` 错误码。网络 `requestId` 和 `expectedVersion` 不参与业务摘要。旧回执没有摘要时保留原重放行为，无法追溯校验其原请求。摘要仅保存在回执存储 JSON，不加入 `CommandResult` 或公开状态。`FORBIDDEN` 用于观战或被替换连接操作；`INVALID_INPUT` 用于原接口边界的参数错误；`SAVE_FAILED` 不包含数据库细节。

观战的公开玩家没有手牌和手牌数量，公开日志不包含抽卡类型或数量。待确认报价内容仅交易双方收到，公共状态仅有 `tradePending` 标志；交易完成后的资金和地产结果进入公开记录。

## 全图事件的兼容扩展

分类规则集保留原信封、`expectedVersion`、`phase` 与 `pending`。全体扣款等待费用结算时，`turnIndex` 仍是原回合玩家，`pending.playerId` 是当前付款人。前端按后者启用资产管理与付款；报价等待时仅允许报价双方按原权限取消或回应，不能据此操作其他人的资产。离线暂停跟随付款人及报价接收人，Flowable 报价等待者为接收人，报价结束后返回付款人。

公开快照继续保留可省略的 `chanceEventDescriptions: string[]` 和 `players[].trapImmunityTurns: number`。前者仅为当前配置的三项扩展机会玩法说明，恢复时刷新，后者为剩余后续个人回合数（零表示无状态）。旧快照缺省按空列表和零处理。内部全图帧、队列、随机补偿样本、状态来源和流程标识不进入公开投影。旧客户端命令仍兼容，新局跨玩家偿债需刷新到支持 `pending.playerId` 的前端。

实际灾害事件、补偿订阅、随机样本及支付标记仅在服务端内部使用；相同命令和快照协议继续有效。

## 经济、地区与资产榜扩展

公开快照新增 `economy: { moneyMultiplier, rentBasePercent, fixedAmounts }`，均为公开经济配置；新局保存实际金额及基础租金百分比，默认比例为 25。已有对局使用保存的比例；旧同格式快照缺少 `economy` 时按一倍基准，缺少 `rentBasePercent` 时保留原 10% 租金。客户端展示建造、租金、卖出金额必须使用当前房间的参数，不能重复乘倍率；租金先按比例计算基础整数金额，再乘等级倍率，固定金额覆盖优先。`board[].regionId`、`regionName` 是可选命名元数据，旧地图按 `district` 显示原街区名，事件暂不按地区筛选。

`players[].netWorth` 为整数成本净资产，`assetRank` 为并列名次（已破产为 null）。所有玩家和观众收到相同数值。已抵押地产按 `max(0, 当前土地建筑成本 - 固定赎回费用)` 计权益；榜单不包含私人手牌估值。排名目标的随机并列选择尚未接入事件能力。

公开房间增加可选 `mapSize: small | medium | large`，缺省为大。房主在大厅通过 `setMapSize` 命令与 `action.mapSize` 设置，新局分别按 `16＋人数×4／6／8` 生成，支持 24–64 格。开始后禁止修改，再开沿用；其他玩家和观众只读同一公开设置。34／46 格为矩形闭环。动作中的地产 ID 协议上限为 63，领域层继续核对当前实际棋盘长度、产权和合法目标，不因协议范围变大放宽这些权限。

新设置命令仍使用原 `expectedVersion`、命令 ID、房间锁和事务提交。非设置操作的空 `mapSize` 不参与 action 摘要，保持已有回执兼容；设置操作的具体大小参与摘要校验。

## 强制费用与资产抵债

所有正数 `PAY_FEE` 和全体费用目标都创建支付选择，不因现金足够、抵押后筹足或银行估值不足自动扣款/清算。租金使用原 `rent`，其他费用使用原 `debt`；金额零直接完成。`pending.amount` 表示尚待支付余额，新增可选 `pending.id` 标识具体债务。旧待选缺少 ID 时，首次偿债报价由服务端补齐；决策键仍沿用原字段，未增加 ID 以改变既有任务关联。

| 命令 | 参数与行为 |
| --- | --- |
| `payDebt` | 无额外参数；当前付款人确认用现金付清余额，不足时拒绝 |
| `rentDecision` | 原 `useCard` 保留；`false` 确认现金付租，`true` 使用原免租卡 |
| `sellBuilding` / `mortgage` / `sellLand` | 原 `tileId`；可以在租金或费用等待中变现，筹足仍需手动支付 |
| `tradeOffer` | 原参数加可选整数 `debtCredit`，省略或零为普通交换；仅玩家债务允许插入报价，系统费用不允许 |
| `tradeRespond` / `tradeCancel` | 原参数与权限；拒绝或主动取消后保留费用，接受后原子交换并抵扣 |
| `declareBankruptcy` | 无额外参数；债务人主动清算，现金加银行可变现资产足够时拒绝；系统费用须先自行抵押可用地产 |

`trade.debtId` 由服务端关联当前待支付事项，不接受客户端指定。`debtCredit` 必须非负、不超过剩余欠款，正数只允许向债权人提供至少一块地产；向第三人出售资产时必须为零。抵债金额由双方协商，不限于银行估值，对应部分不转移现金；可抵清或部分抵扣继续等待。报价中的现金仍为交易对价，余额只减少 `debtCredit`，剩余费用另用 `payDebt` 确认支付。报价内容仍只有双方可见，成交抵扣金额与余额进入公开日志。

棋盘新增可选 `board[].mortgageBase`：整体抵押时的土地加建筑成本估值。抵押取得其 50%，赎回付其 55%；旧已抵押地产缺省按土地价计算。建筑保留、停止收租，抵押建筑不可单独卖出，赎回基数不随拆房变化并随产权转移。租金和费用等待中禁止赎回。全体批次仍保存目标与下一目标，逐人确认完成后继续。

命令摘要在 `debtCredit` 省略或零时移除该新键，保持已有回执摘要兼容；正数参与去重校验。金额和上下文仍由领域校验，继续使用房间锁、预期版本和同事务快照/回执。玩法选择、整段偿债和单份报价均不限时，报价保留到主动接受、拒绝或取消；相关玩家离线时保留待选，重连继续。系统费用确认清算前须自行抵押可用地产，且现金仍不足。

旧报价字段 `remainingMs` / `runningSince` 仅为协议与快照兼容保留，服务端刷新或恢复时分别清零、置空，不参与到期判定。旧存档中的报价即使剩余时间已为零也不会自动取消。前端移除倒计时计算与提示；网络认证、心跳检测和请求等待超时继续使用原口径，只管理连接或查询已提交结果，不自动替玩家完成游戏选择。

本轮仅完成后端编译、前端类型检查和差异静态检查，未做真实联机、重连或重启验收。旧客户端指令保留，但旧界面可能无法在新的租金选择中管理资产或确认一般费用，须刷新前端后使用新流程。
