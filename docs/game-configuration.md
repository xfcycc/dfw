# 地区地名与经济配置

新局的地区地名和金额分别放在独立 JSON 文件中，不需要修改地图生成代码。房主在大厅设置小／中／大地图，分别为 `16 + 人数 × 4／6／8`，默认大地图；2–3 人机会与财富各两格，4–6 人各三格，数量不随大小变化。完整玩法确认见 [内容设计](game-content-design.md)。

## 房间地图大小

大小通过房主的大厅选择控件保存到房间 `mapSize`，值为 `small`／`medium`／`large`。开局后不能修改，再开保留选择；重新启动后的同格式房间按保存值恢复，旧房间缺少设置时默认大。进行中已生成棋盘不重建。设置不是全局配置文件，不影响其他房间。

| 人数 | 小：16＋人数×4 | 中：16＋人数×6 | 大：16＋人数×8 |
| --- | --- | --- | --- |
| 2 | 24 | 28 | 32 |
| 3 | 28 | 34 | 40 |
| 4 | 32 | 40 | 48 |
| 5 | 36 | 46 | 56 |
| 6 | 40 | 52 | 64 |

中地图的 34／46 格按长短边交替组成矩形；前端行列与四角均使用整数坐标，不把总格数改为四的倍数。金额与机制概率不会因大小自动变化。

## 地区地名池

默认文件：[map-regions.json](../backend/src/main/resources/game-rules/map-regions.json)。外部文件可通过 `GAME_RULES_MAP_REGIONS=file:/srv/dfw/rules/map-regions.json` 或 Java 参数 `--game.rules.map-regions=...` 指定。

```json
{
  "regions": [
    {
      "id": "delta",
      "name": "三角洲地区",
      "names": ["零号大坝", "航天基地", "长弓溪谷", "巴克什", "潮汐监狱", "核电站"]
    },
    {
      "id": "mainland",
      "name": "大陆现实地区",
      "names": ["北京", "上海", "广州", "深圳", "杭州", "南京"]
    }
  ]
}
```

默认池包含三角洲、大陆现实、宝可梦关都／城都／丰缘／神奥、原神蒙德／璃月、火影忍者、西游记、世界城市，以及原创烟火夜市／海岛度假／奇幻小镇，共 14 组。新增十组各含八个地名，仅扩充命名池，不调整地面材质。地图先用独立地图种子打乱地区组，再按边分配优先地区；少于四组时循环分配。组内地名也打乱，整张地图共用未使用地名池；优先地区的地名用完后，按打乱顺序从其他地区补齐。

同一张地图的地产地名不得重复，也不再追加 `·2号` 等后缀；跨地区的同名地点也只使用一次，并避开起点等特殊格名称。配置要求至少一组、地区 ID 唯一、组名与地名非空、同组地名不重复；全部地区的不同地名总数还须足以覆盖本次地图的地产数量，否则生成时提示补充配置。地点名是主题地段名称，不要求虚构地点具有独立真实行政区划。

每格保存 `regionId` 与 `regionName`，补齐地名时保存其实际来源地区；`district` 继续表示第 0–3 边，用于地图颜色和坐标。特殊格显示起点等自身名字，但也保存所在边的优先地区元数据。地块详情只显示地块名称，不再展示地区主题标签；非对局地图图例仍使用地区元数据。

地区只影响命名，不筛事件、不改变价档、不产生地区技能。地图种子与地区配置相同才可重算相同地图；已开始的局直接保存生成结果，不因更换命名文件重命名。三角洲地点也可参考 [发行方 App Store 更新说明](https://apps.apple.com/cn/app/%E4%B8%89%E8%A7%92%E6%B4%B2%E8%A1%8C%E5%8A%A8/id1642894547) 与 [地图工具更新记录](https://www.3839.com/hykb/hykb_tools/sjz/kdz/)。宝可梦主题参考 [宝可梦官方关都城镇介绍](https://www.pokemon.co.jp/ex/pika_vee/story/180713_07.html)；中文地名以项目配置为准，可自行调整。

## 金额配置

默认文件：[economy.json](../backend/src/main/resources/game-rules/economy.json)。外部文件使用 `GAME_RULES_ECONOMY=file:/srv/dfw/rules/economy.json`，Java 参数为 `--game.rules.economy=...`。

```json
{
  "moneyMultiplier": 2,
  "rentBasePercent": 25,
  "fixedAmounts": {}
}
```

`moneyMultiplier` 为正有限数，现金常量按倍率四舍五入为整数。固定金额均为最终值，优先于倍率，不再次放大。百分比、概率、步数、回合数、牌数和玩家交易输入不乘倍率。新局按开局人数确定每人初始现金基数：2 人为 6000，3～4 人为 10000，5～6 人为 15000；默认 ×2 后分别为 12000、20000、30000。初始手牌为 2 人每人 2 张，3 人及以上每人 3 张。起点收入仍为 2000；基准地价为 400／600／800／1200／1600，默认 ×2 后为 800／1200／1600／2400／3200。

`rentBasePercent` 为 0～100 的整数百分比，默认文件为 25。基础租金为 `floor(实际地价 × rentBasePercent ÷ 100)`，再乘 0～3 级倍率 `[1,3,6,10]`。每边先打乱五档顺序，再尽量均衡分配并打乱位置；不足完整五档的一组随机选择剩余价档，不固定优先低价档。已有外部配置缺失比例字段时沿用原 10%，使用新口径需显式补入 `rentBasePercent: 25`。

| 配置键 | 作用 | 无覆盖时 |
| --- | --- | --- |
| `initialCash` | 每人初始现金 | 按开局人数：2 人 6000、3～4 人 10000、5～6 人 15000，再 × 倍率 |
| `startIncome` | 向前或后退经过、到达起点或原地停留 | 基准 1000 × 倍率 |
| `landPrice.0`、`.1`、`.2`、`.3`、`.4` | 五档地价 | 基准 400／600／800／1200／1600 × 倍率 |
| `buildCost.<实际地价>` | 每级建筑成本 | 实际地价 ÷ 2 |
| `sellBuilding.<实际地价>` | 出售一级未抵押建筑 | 实际建筑成本 ÷ 2 |
| `sellLand.<实际地价>` | 出售未抵押空地 | 实际地价 ÷ 2 |
| `rent.<实际地价>.<等级>` | 对应价档、0–3 级租金 | `floor(实际地价 × rentBasePercent ÷ 100)` × `[1,3,6,10]` |
| `<规则ID>.<步骤序号>.amount` | 现金效果最终金额 | 常量 × 倍率；动态金额使用已计算值 |

价档派生键中的价格是实际地价。例如默认 ×2 后高档地价为 3200，所以使用 `rent.3200.3`，而非 `rent.1600.3`。地价改为 5000 后，其派生覆盖键也应使用 5000。没有固定覆盖时建造与租金已经由实际地价放大，不再乘一次倍率。

现金步骤包括 `GRANT_MONEY`、`PAY_FEE`、`CHARGE_ALL`。步骤序号从 0 开始，ID 使用行为 JSON 中的 `id`，例如 `chance_fee.0.amount`。现金金额若引用 `actor.cash` 等已经是实际现金的值，不再次乘倍率；现金日志用 `{effect.amount}` 展示最终金额。其他效果中的 `amount`（如 MOVE、DRAW_CARDS）不受经济倍率影响。

以下只是可选覆盖示例，未启用：

```json
{
  "moneyMultiplier": 2,
  "rentBasePercent": 25,
  "fixedAmounts": {
    "initialCash": 16000,
    "startIncome": 3000,
    "rent.3200.1": 1200,
    "chance_fee.0.amount": 500
  }
}
```

各文件在服务启动时加载、校验，不在游戏中热替换。基础地价必须大于零；金额非负且需处于 JavaScript 安全整数范围内。字段名写错不会自动推断为另一个金额键，配置时应与规则 ID 和步骤顺序核对。

## 本局保存与恢复

大厅先使用当前配置预览新局的初始现金与起点收入，再开一局或恢复大厅时刷新预览。开始新局时，把经济配置及 `rentBasePercent` 复制到 `Room.economy`，并把初始现金、起点收入、地价和当时规则的固定现金步骤展开成最终金额保存。生成后的地产实际价格、地区和名字也随棋盘保存。修改金额、租金比例或地区文件并重启，已开始的局保持保存的金额、租金比例与地图，新局使用新配置。

动态引用仍在效果生成时按当时状态计算；已入队效果使用保存的具体金额。没有 `economy` 字段的同格式进行中快照采用原一倍基准；缺少 `rentBasePercent` 的同格式快照继续按原 10% 基础租金，已保存 50% 等比例的对局也保持其原比例，不直接把已有现金、地价或待付租金重算；这不代表提供了旧引擎格式迁移。

行为规则仍统一使用重启后加载的当前规则集，没有完整规则包版本冻结。进行中对局不要修改既有规则 ID、步骤顺序或效果结构，否则保存的步骤金额键与新结构可能不对应。纯金额与地名配置可以按上述新局边界修改；新增或变更行为结构仍需专门评审恢复兼容性。

## 四档内容配置（2026-10-15）

机会、财富、道具的普通随机抽取统一为 R 40%／SR 30%／SSR 25%／UR 5%，等级内完整效果等概率、匹配卡面等概率。`content.mechanisms` 用 `enabled` 控制停用，`groups` 只组织数据，`parameters[].rarity` 决定实际影响档；旧机制／金额档 `weight` 字段已移除。使用 `GAME_RULES_CHANCE_EVENTS`、`GAME_RULES_FORTUNE_EVENTS`、`GAME_RULES_CARD_EVENTS` 外部文件的环境须同步新结构。完整等级、UR 及定向补给例外见 [内容运行说明](game-content-runtime.md)。规则在进程启动时加载，修改文件需重新启动；旧冻结手牌不重抽，存档恢复的规则摘要校验不放宽。
